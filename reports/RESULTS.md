# Сводка результатов проекта

Этот отчёт даёт краткую хронологическую картину текущего состояния проекта. Машиночитаемый источник метрик — [../experiments/results.csv](../experiments/results.csv); подробная история MOO-запусков вынесена в [MOO_EXPERIMENT_HISTORY.md](MOO_EXPERIMENT_HISTORY.md).

## 1. Данные

Основной экспериментальный протокол — протокол B на KuaiRand-Pure / KuaiRand-27K. После 5-core фильтрации получен контрольный отпечаток `23 951 users / 7 111 items / 1 134 420 interactions`; он совпадает с ожидаемым fingerprint из [../outputs/data/protocol_b_manifest.json](../outputs/data/protocol_b_manifest.json).

| Split | Interactions | Users |
| --- | ---: | ---: |
| Train | 1 086 518 | 23 951 |
| Validation | 23 951 | 23 951 |
| Test | 23 951 | 23 951 |

Разбиение хронологическое: train содержит историю до двух последних interactions пользователя, validation — предпоследний interaction, test — последний interaction. Максимальная длина последовательности в RecBole-конфигурации равна `50`.

## 9. Использование TEST

Stage 1, Stage 2 и Stage 3 не использовали TEST для выбора методов, гиперпараметров или конфигураций. Выбор архитектуры EPO + MoE также должен выполняться только по валидационной выборке.

TEST уже использовался в исторических строках базовых моделей и воспроизведений, перечисленных выше. Для нового финального метода TEST должен оставаться закрытым до frozen evaluation.

## 10. Открытые вопросы

- Статус Slurm jobs M0/M2/M4/M8 нужно читать с кластера и добавлять только после появления committed artifacts.
- Для EPO + MoE пока нет зафиксированных validation results, поэтому нельзя выбирать архитектуру.
- Внутри-семейный выбор representatives MOO требует отдельного literature audit; текущие строки Stage 1 — рабочие representatives/adaptations.
- Финальный собственный метод ещё не зафиксирован, и TEST для него не запускался.
