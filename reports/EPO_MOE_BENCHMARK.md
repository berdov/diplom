# Эксперимент EPO + MoE

Этот отчёт описывает текущий этап проекта: сравнение EPO без MoE и EPO со смесью экспертов (Mixture of Experts, MoE) только по валидационной выборке поверх той же базовой архитектуры `MultitaskTiM4Rec`. TEST должен использоваться только после фиксации EPO+MoE конфигурации.

## Постановка эксперимента

Сравниваются четыре варианта:

| Вариант | Смысл | Job ID |
| --- | --- | ---: |
| M0 | TiM4Rec + MTL + EPO без MoE | 4300861 |
| M2 | TiM4Rec + MTL + EPO + MoE с 2 экспертами | 4300862 |
| M4 | TiM4Rec + MTL + EPO + MoE с 4 экспертами | 4300863 |
| M8 | TiM4Rec + MTL + EPO + MoE с 8 экспертами | 4300864 |

Во всех вариантах сохраняются:

- один набор данных и один протокол B;
- одна базовая архитектура TiM4Rec;
- один набор задач: `rank`, `is_click`, `long_view`, `is_like`, `is_profile_enter`;
- одна настройка EPO и одна метрика выбора модели: `ranking_operating_point.NDCG@10`;
- выбор архитектуры только по валидационной выборке.

Меняется только наличие и число экспертов. Текущая реализация MoE является плотной (dense): вычисляются все эксперты, а отдельный механизм маршрутизации для каждой задачи смешивает их выходы. Это не разреженная top-k MoE.

Диагностика маршрутизации будет заполняться только после появления зафиксированных артефактов с результатами на валидационной выборке. Для MoE важно отслеживать не только метрику ранжирования, но и использование экспертов: есть ли доминирующий эксперт, не возникает ли коллапс маршрутизации, то есть концентрация почти всей массы на одном или нескольких экспертах, различаются ли механизмы маршрутизации для разных задач.
