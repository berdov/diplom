## UNPINNED/UNKNOWN VERSIONS

- Upstream фиксирует зависимости только в `environment.yaml`; отдельного `requirements.txt`,
  `setup.py` или `pyproject.toml` нет.
- Stdlib imports отдельно не version-pinned.
- Версии cluster driver/runtime фиксируются из фактического Slurm job, не из
  upstream.
- `MAX_ITEM_LIST_LENGTH=50` задан в config, но при upstream `var_len=True`
  `SSD4RecDataset.data_augmentation` сохраняет полные variable-length histories.

## Рекомендуемая команда создания

На cHARISMa:

```bash
module load Python/miniconda || true
conda env create -p /home/daryumin/iberdov/diplom/envs/ssd4rec \
  -f /home/daryumin/iberdov/diplom/experiments/ssd4rec_baseline/upstream/environment.yaml
```

Если exact upstream solving недоступен на login node, допустимый fallback -
создать отдельный clone уже рабочей TiM4Rec-среды в отдельном пути и затем
зафиксировать SSD4Rec-specific wheels там. Это все равно должно быть
`/home/daryumin/iberdov/diplom/envs/ssd4rec` или другой SSD4Rec-only путь, но
не изменение TiM4Rec environment in place.

## Команды smoke и sanity

Smoke:

```bash
sbatch slurm/ssd4rec_baseline.sh
```

Five-epoch sanity:

```bash
SSD4REC_STAGE=sanity sbatch --job-name=ssd4rec-sanity --partition=test slurm/ssd4rec_baseline.sh
```

Jobs используют E-node через `--constraint=type_e`; sanity останавливается после
5 эпох и не запускает full run.
